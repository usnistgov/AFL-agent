AFL.double_agent.BoTorchMixin module#

BoTorch machinery shared by the GP regressors, classifiers and acquisition ops.

Everything BoTorch specific lives on BoTorchMixin: the lazy import of the optional dependency, the tensor helpers that move data between xarray and torch, GP construction, and the bound helpers that read a PipelineOp’s own attributes so an op can call self.candidates(dataset) instead of threading the same variable and dimension names through every call. ScoreFunctionAcquisition is the one module-level object: a torch.nn.Module adapter for user score functions.

class AFL.double_agent.BoTorchMixin.BoTorchMixin#

Bases: object

All BoTorch machinery an op needs, as methods on one class.

Mix this into a PipelineOp subclass (list it before the op base class) and call _init_botorch() at the end of __init__.

The class has two layers. Stateless helpers (static/class methods such as optimization_bounds_to_tensor(), fit_single_task_gp(), evaluate_acquisition_on_grid()) take explicit arguments and can be called on the class itself, e.g. BoTorchMixin.fit_single_task_gp(train_x, train_y). Bound helpers (candidates(), bounds_tensor(), load_model(), optimize_acqf(), …) read the following attributes, which the op sets itself:

grid_variable, grid_dim

Candidate grid and the dimension indexing its points; the last remaining dimension (or component_dim if the op defines one) indexes components.

feature_input_variable, predictor_input_variable, sample_dim, objective_direction

Only needed by training_data() (regressors).

bounds, is_simplex, model_variable, model_uri, num_restarts, raw_samples

Set by _init_botorch().

The mixin does not define __init__ so it composes with any PipelineOp constructor signature.

static make_simplex_constraints(n_dim: int) → list[tuple[Tensor, Tensor, float]]#

Return BoTorch-compatible simplex constraints.

BoTorch’s optimize_acqf accepts linear inequality constraints of the form

\[\sum_i a_i x_i \ge b.\]

A simplex equality \(\sum_i x_i = 1\) is therefore encoded as the pair

\[\sum_i x_i \ge 1, \qquad -\sum_i x_i \ge -1,\]

which together are exactly equivalent to the equality constraint.

class AFL.double_agent.BoTorchMixin.ScoreFunctionAcquisition(function, kwargs: Mapping[str, Any] | None = None)#

Bases: Module

Adapt a user score function to BoTorch’s acquisition interface.

The wrapped function scores one candidate set: it receives X with shape (q, d) (q jointly proposed design points, no batch dimension) and returns a single scalar, higher being better. This module adds BoTorch’s batch handling: a (b, q, d) input is scored one candidate set at a time and returned as (b,).

X is a torch.Tensor so that torch-based functions are optimized with exact gradients. Functions that work on NumPy arrays also work: if the function cannot handle a tensor that requires gradients, or returns something without autograd history, it is called on a detached tensor (which NumPy accepts as an array) and differentiable is set to False so that the optimizer switches to finite differences.

kwargs are the static args of the acquisition spec, with any Variable placeholders already resolved; the function is called as function(X, **kwargs).

forward(X: Tensor) → Tensor#

Define the computation performed at every call.

Should be overridden by all subclasses.

Note

Although the recipe for forward pass needs to be defined within this function, one should call the Module instance afterwards instead of this since the former takes care of running the registered hooks while the latter silently ignores them.
